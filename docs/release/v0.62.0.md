# v0.62.0: Reviewer Workflow Polish

Date: 2026-10-31

The container scan blocked this tag's publication because of the bundled certificate store in the pinned uv tool. See [v0.62.1](v0.62.1.md) for the security-corrected release; these implementation notes remain for tag history.

This update makes everyday exception review safer and easier to navigate while preserving existing API clients and saved resolution history.

## Added

- Unsaved-resolution confirmation before changing records, filters, pages, identity, organization, or workspace sections; cancel keeps the current draft
- Navigation protection while a save is pending, confirmation before stale-record refresh, and supported-browser warnings before reload or close
- Server-side oldest-first, newest-first, and highest-severity sorting with stable timestamp/ID tie-breakers
- Filtered matching totals, visible result ranges, page counts, and reliable last-page detection
- Automatic return to the last valid page when a resolution removes the final matching issue from the current page
- Remembered status, severity, and sorting in this browser tab, scoped separately to identity and organization
- A Reset filters command and safe fallback when stored preferences are malformed or browser storage is blocked
- Regression tests across API permissions, sorting, page boundaries, draft protection, preference isolation, and the desktop/mobile browser workflow
- Compatible frontend security updates and targeted Python dependency-lock refreshes for reported advisories

## Use It

From the updated repository folder, run:

```bash
python3 scripts/demo.py
```

Use `python` on Windows. Open **Exceptions**, choose a **Sort order**, and inspect the matching result range. Start a resolution note, then try switching records or workspace sections: cancel keeps the draft. Return to the desk to restore your menu selections. **Reset filters** returns to the default view.

The [beginner demo guide](https://imtiazither.github.io/eduwork-databridge/docs/guides/demo-quickstart/) covers setup; the [exception desk guide](https://imtiazither.github.io/eduwork-databridge/docs/guides/exception-desk/) covers the review workflow.

## Compatibility and Privacy

No new database migration or breaking change to existing list clients is introduced. `GET /api/v1/quarantine` still returns a list; its optional `sort` parameter defaults to `oldest`. The new `GET /api/v1/quarantine/page` returns `items`, `total`, `limit`, and the effective `offset`, using the same organization and permission checks. Out-of-range offsets are clamped to the last valid page. Counts can change when another reviewer updates the database.

Only the three menu selections are remembered in session storage. Notes, free-text searches, selected records, page offsets, and snapshot IDs are not stored there. Draft notes remain in memory until explicitly saved or discarded. Browser unload warnings cannot guarantee recovery after every mobile/browser shutdown; a warning is not autosave. Queue refresh is explicit so focusing another window cannot silently replace an edited record.

The public GitHub Pages case remains a static synthetic preview. These connected workflow improvements run with the local API. A recorded resolution remains a human review outcome, not an automatic correction or publication approval.
