# v0.16.0: Auditable Match Decisions

## Summary

v0.16.0 turns the existing reversible `MatchDecision` data model into a protected, documented API workflow. It is a small human-review milestone: an authorized reviewer can record a reasoned decision, revise it without losing history, and inspect the decision history for the candidate.

## Added API endpoints

- `POST /api/v1/matches/{candidate_id}/decisions`
- `GET /api/v1/matches/{candidate_id}/decisions`

The write endpoint requires an organization scope and the `matching:write` permission. It accepts one of `match`, `no_match`, `defer`, or `escalate`, plus a non-empty reason. The authenticated actor becomes the reviewer of record.

## Evidence and reversibility

- A later decision links to the decision it supersedes.
- The history endpoint returns the most recent decision first.
- Each write emits the `matching.decision.recorded` audit event.
- The audit event contains decision metadata, not the review reason itself.

## Boundaries

- The public GitHub Pages reviewer desk remains a static, non-persistent synthetic demonstration.
- This release does not add a predictive model, automated intervention, real partner data, or production identity integration.
- Production deployments must replace demo identity with verified OIDC claims and validate their own privacy, access, retention, and compliance requirements.
