# v0.62.1: Reviewer Workflow Polish

Date: 2026-10-31

This release delivers the reviewer workflow improvements and a security fix for the build tool used by the container and release workflows.

## Added

- Confirmation before discarding an unfinished resolution when changing records, filters, pages, identity, organization, or workspace sections
- Protection during a pending save and supported-browser warnings before leaving or reloading a page with an unfinished note
- Stable server-side oldest-first, newest-first, and highest-severity queue sorting
- Accurate filtered result ranges and page totals, reliable last-page detection, and recovery after resolving the last matching issue on a page
- Remembered status, severity, and sort order, scoped by identity and organization, plus a Reset filters command
- API, frontend, and desktop/mobile real-browser regression tests
- Compatible frontend and Python dependency security updates

## Security Fix

The v0.62.0 container scan correctly blocked publication because uv 0.11.29 bundled an affected certificate authority. This release pins uv 0.13.4 in the container and all workflows, raises the demo checker's minimum version, and adds regression checks for those pins. It addresses [GHSA-hq85-5cpj-mr62](https://github.com/advisories/GHSA-hq85-5cpj-mr62). The existing v0.62.0 tag is not rewritten.

## Try It

Update the repository folder, install Python 3.12 or 3.13, uv 0.13.4 or later, and Node.js 24 LTS. Run:

```bash
python3 scripts/demo.py
```

Use `python` on Windows. In **Exceptions**, select a sort order and inspect the matching result range. Start a note, try changing records or sections, and cancel to retain it. Return to restore your menu selections. See the [beginner guide](https://imtiazither.github.io/eduwork-databridge/docs/guides/demo-quickstart/) and [exception desk guide](https://imtiazither.github.io/eduwork-databridge/docs/guides/exception-desk/).

## Compatibility and Privacy

No new database migration is required. The original quarantine list response remains unchanged. The additive `/api/v1/quarantine/page` endpoint returns `items`, `total`, `limit`, and effective `offset`, with the same identity, organization, and permission checks. See the v0.62.0 implementation notes for API details.

Only status, severity, and sorting are remembered in session storage. Draft notes, search text, selected records, offsets, and snapshot IDs are not stored there. A browser warning is not autosave and cannot guarantee recovery after every device shutdown. Public GitHub Pages examples remain static and synthetic; the local API provides saved review outcomes.

## Verification

The release manifest records local tests, coverage, security checks, artifacts, and checksums. Publication requires the full release workflow, including container scanning and signature verification, to pass.
