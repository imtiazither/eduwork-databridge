# v0.50.0: Connected Review Workbench

Date: 2026-10-07

The identity desk now connects to the local API. Reviewers can select an organization, inspect comparison evidence and prior decisions, search and filter candidates, and save a reasoned decision that remains visible after refresh. The public Pages experience keeps its clearly labeled synthetic preview.

## Added

- Connected identity-review UI with workload counts, attention and status filters, record-key search, pagination, candidate evidence, and decision history
- Explicit synthetic candidate generation for an empty local queue
- Candidate and decision revisions, bounded history, and HTTP 409 rejection of stale decisions
- Atomic decision and audit persistence, with regression coverage for competing writers and audit failure rollback
- Queue aggregation and an organization/status/order index
- Revision backfill that preserves existing decision reasons, reviewers, and supersession links
- Explicit identity, permission, tenant isolation, and pre-read snapshot-scope regression tests

## Fixed

- Anonymous requests could previously inherit the demo administrator identity
- Organization/source metadata, source connection/discovery, profiling, and quarantine resolution now authenticate and check permissions
- Snapshot ownership is checked before file reads and source lineage attribution; profile baselines must belong to the organization and the same source object
- Quarantine resolution attributes the reviewer to the authenticated actor and emits an audit event
- Probabilistic matching blocks conflicting trusted IDs across clusters, including links through missing-ID records, and rejects duplicate record keys
- The initial migration now freezes the pre-0.50 schema instead of importing changing application metadata
- Retention honors the configured export root
- Existing lint/format failures and the source-map-js advisory [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q), patched by the locked 1.2.2 version
- Three urllib3 advisories affecting the former 2.7.0 lock, fixed by 2.8.0: [unbounded chunk-size buffering](https://github.com/urllib3/urllib3/security/advisories/GHSA-vxq7-64xx-v4gw), [Deflate streaming loop](https://github.com/urllib3/urllib3/security/advisories/GHSA-gh4c-6fx4-qh6g), and [HTTPS proxy TLS configuration](https://github.com/urllib3/urllib3/security/advisories/GHSA-8988-9cw3-xx77)
- Release verification now regenerates benchmark and backup reports and rejects evidence from a different version

## Upgrade

Back up the control database, install the committed lockfiles, and run:

```bash
uv sync --frozen --extra dev
npm --prefix apps/reviewer-ui ci
uv run alembic upgrade head
uv run python -m eduwork_databridge.seed
```

Revision `20261007_0005` adds a candidate revision and sequential decision revisions. Existing history is ordered by decision time with UUID tie-breaking for equal timestamps. Fresh databases and existing v0.20 databases take the same migration path. The new revision can be downgraded without discarding decision history. Migration tests exercise SQLite; target PostgreSQL deployment validation remains outstanding.

Update API clients for these contract changes:

- Every protected demo request must explicitly send `X-Demo-User`; missing identity returns 401.
- Source connection/discovery now require `X-Organization-ID` and registered organization-owned source metadata.
- Decision POST bodies require `expected_revision`. Read it from the queue; a stale value returns 409. Omission or a negative value returns 422.
- Quarantine resolution no longer accepts a caller-supplied `reviewer_id`. The server records the authenticated actor.
- Decision history defaults to 50 rows and supports `limit` (1–200) and `offset`.
- Queue status filters accept documented states only; mapping preview limits are bounded to 1–1000.

## Evidence and limits

Local verification passed 92 Python tests with 90.86% coverage, 16 frontend tests, strict lint/types/docs, migration upgrade/downgrade with existing history, benchmark budgets, SQLite backup/restore, and a fresh Python 3.12 wheel installation. Python and frontend dependency audits report no known vulnerabilities. A browser smoke check saved a synthetic decision, confirmed persistence after reload, and checked the viewer permission boundary.

See the [release manifest](../evidence/release-manifest.json), [connected desk screenshot](../guides/review-workbench.md), and verification reports under `release/` for measured checks. The older screenshots, PDFs, and video illustrate the synthetic case file. They do not demonstrate the new connected review controls.

Decisions update candidate status and append review evidence; they do not rewrite source records or published outputs. This update does not claim production OIDC, deployed PostgreSQL concurrency, customer adoption, calibrated probabilities, or business outcomes.
