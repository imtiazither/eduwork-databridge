# v0.60.0: Connected Exception Desk

Date: 2026-10-18

The Exceptions screen now connects to saved validation issues. Reviewers can find held records, inspect the rule and masked evidence, record a resolution with a reason, and revisit the full resolution history after refresh.

## Added

- Organization-scoped exception queues with status and severity filters, record/rule search, bounded pagination, and workload counts
- An evidence inspector showing the affected field, source snapshot, validation rule, explanation, and remediation guidance
- Saved resolution notes, authenticated reviewer attribution, optional corrected-snapshot links, and append-only revision history
- Acknowledge, record correction, waive, close, and reopen actions with required notes
- Revision checks that reject stale resolutions with HTTP 409, plus atomic resolution/status/audit writes
- A history-preserving database upgrade that imports the latest legacy note and prevents destructive downgrades after new resolutions
- A source-validation demo that supplies nine synthetic missing-employee-ID issues for the desk
- API, concurrency, rollback, migration, and frontend workflow regression tests

## Fixed

- The backend CI import-order failure in `tests/factories.py`
- The connected navigation no longer labels the exception queue with the unrelated fixed example count

## Upgrade

Back up the control database, then run:

```bash
uv sync --frozen --extra dev
npm --prefix apps/reviewer-ui ci
uv run alembic upgrade head
uv run python -m eduwork_databridge.seed
uv run python scripts/run_demo.py
```

Start `make api` and `make ui`, then open **Exceptions** in the local reviewer desk.

API clients must now send `expected_revision` with `POST /api/v1/quarantine/{id}/resolve`. Read the revision from `GET /api/v1/quarantine`; a stale value returns 409, and omission returns 422. The response contains the recorded resolution and its revision. New routes provide the queue, `GET /api/v1/quarantine/summary`, and `GET /api/v1/quarantine/{id}/history`. All require explicit identity, organization membership, and `validation:write`.

Migration `20261018_0006` preserves the latest existing note as an imported history entry. Downgrades are blocked after new resolution history has been recorded; retain the pre-upgrade backup.

## Verification and scope

Verification passed 99 Python tests with 91.18% coverage and 24 frontend tests. Checks include strict types and formatting, database upgrades, concurrent resolutions, audit rollback, generated contracts, documentation, benchmarks, dependency audits, fresh wheel installation, and release checksums. A browser check saved a synthetic resolution, confirmed its history after reload, checked the viewer permission boundary, and verified desktop/mobile layouts.

Public examples use synthetic data. A saved status records a review outcome; it does not edit source records or independently approve data for publication. The GitHub Pages example remains a static preview.
